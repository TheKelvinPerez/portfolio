# Portfolio Design Spec And Brand Guidelines

Created July 8, 2026

## Design Read

The portfolio should feel like a personal developer field journal inside a cosmic workspace. The Laravel proof needs to feel like the clearest technical artifact in that world, not like a separate SaaS landing page dropped into the middle of it.

## Brand Goal

Position Kelvin as a full stack Laravel developer who can also design polished product interfaces, understand business context, work across WordPress and ecommerce systems, and ship infrastructure when needed.

The site should communicate three things quickly.

1. I can build real Laravel applications.
2. I have a longer product and client journey behind that skill.
3. I am honest about what worked, what did not work, and what the artifact proves.

## What Already Fits

These sections are the visual and emotional baseline.

1. Proof Points

   This section belongs because it uses the existing page atmosphere instead of fighting it. The cards are translucent, purple, simple, spacious, and quiet. The typography is direct. The numbers are clear. The icons are supporting signals, not decorations.

2. The older Timeline

   The older timeline belongs because it has personal history, motion, year based structure, purple cards, small icon circles, and a journey feeling. The copy can change for the Laravel direction, but the visual language should stay close to this pattern.

3. The Gear section

   The gear section belongs because it is personal and physical. It makes the portfolio feel lived in. The bento layout, images, soft dark panels, and hover movement fit the site better than a pure corporate case study grid.

4. The Books section

   The books section belongs as a personality layer. It should not compete with the Laravel proof, but it helps the site feel human and self directed. If it returns to the home page, it should sit after the core technical proof.

5. The older FAQ

   The old FAQ belongs because the chat style has personality. The copy needs to be rewritten for the Laravel role, but the interaction and visual language fit the portfolio.

## What Drifted

The current Dashboard Proof section has the right content, but the wrong visual world.

1. It creates a separate slate, cyan, and emerald system that does not match the purple field.
2. The large black feature panel feels heavier than the rest of the page.
3. It uses too many boxed regions inside boxed regions.
4. The placeholder slots feel unfinished instead of intentional.
5. The headline makes the agency outcome the main visual moment, when the main moment should be the product artifact.
6. The workflow content is useful, but it is presented like an app feature list instead of a portfolio story.

## Brand Voice

The voice should sound like Kelvin explaining the work directly.

1. Honest.
2. Technical.
3. Personal.
4. Plain spoken.
5. Specific without sounding inflated.

Use first person when the section is about the journey, decisions, lessons, or motivation.

Use product language when the section is about the dashboard, architecture, workflow, or project details.

Avoid corporate polish, hype language, and vague claims unless the section proves the claim with a concrete artifact.

## Core Narrative

The story should move in this order.

1. I am targeting full stack Laravel development.
2. The strongest proof is the Light Code Labs Dashboard.
3. The agency attempt did not get distribution, but the product is real.
4. The product shows Laravel, Inertia, React, TypeScript, APIs, data modeling, queues, applied AI features, Docker, staging, and Hetzner hosting.
5. WordPress is still part of the journey because it built the PHP foundation.
6. Shopify and ecommerce show range, not the main positioning.
7. The timeline explains how the path makes sense.

## Visual System

### Page World

Keep the full page cosmic gradient as the world of the site. Sections should feel like they are floating inside the same atmosphere.

Do not introduce a new dominant background world per section. The dashboard proof section should not become black, slate, cyan, or enterprise blue as its main identity.

### Color Roles

Use these roles consistently.

1. Deep base

   Use near black and deep purple for depth. This is for page grounding, card interiors, and media wells.

2. Primary brand color

   Purple is the primary section and card color. Most panels should live in the purple family.

3. Secondary brand color

   Blue can appear in gradients, timeline years, progress lines, and subtle motion accents.

4. Warm accent

   Gold or yellow can appear in ratings, quotes, small highlights, or human moments. It should feel rare.

5. Utility colors

   Green, cyan, and red are only for states, small signals, or existing hero details. They should not become the identity of a whole section.

### Surfaces

The default card surface is translucent purple glass.

Use this feeling across proof cards, project cards, timeline cards, book cards, and FAQ bubbles.

A card should usually have:

1. Purple border.
2. Purple to deeper purple gradient.
3. Soft blur.
4. Subtle hover glow.
5. Enough inner padding for calm reading.

Avoid:

1. Cards inside cards.
2. Thick black blocks inside the page gradient.
3. Dashed placeholder boxes as primary visuals.
4. New one off accent palettes.

### Shape

The site already uses soft rounded cards. Keep that shape consistent.

1. Large cards use the current soft rounded shape.
2. Small chips and pills may stay fully rounded.
3. Buttons should use the existing button component unless a section has a clear reason not to.
4. Do not mix square enterprise panels with the soft personal cards.

### Typography

The site should keep strong centered section headings and readable supporting text.

1. Hero text can be large and expressive.
2. Section headings should stay compact and centered.
3. Card titles should be smaller than page headings.
4. Body copy should be relaxed, readable, and not dense.
5. Avoid aggressive uppercase labels except for tiny metadata chips.
6. Do not add negative letter spacing to new UI.

### Motion

Motion should feel like the page is revealing a journey.

1. Use staggered entrance motion for card groups.
2. Keep hover movement subtle.
3. Avoid heavy movement on long reading sections.
4. Timeline motion can stay more expressive because it represents time and progression.

## Section Rules

### Hero

Keep the current hero world, circle system, centered headline, and direct CTA structure.

The hero should say the role clearly. It should not try to explain the whole story.

Primary CTA should point to Laravel work.

Secondary CTA should point to contact or resume.

### Proof Points

Use this as the reference section.

Rules:

1. Keep the centered heading.
2. Keep the translucent purple card grid.
3. Keep concise labels and proof numbers.
4. Keep it easy to scan.
5. Do not turn it into a paragraph heavy section.

### Light Code Labs Dashboard Feature

This section should be redesigned around a product artifact, not a feature checklist.

Recommended structure:

1. Centered section heading.

   Example heading: Light Code Labs Dashboard

   Example subheading: A Laravel product dashboard built from an agency attempt.

2. One wide feature card in the same purple glass language as Proof Points.

3. Left side contains the short honest story.

   It should explain that the agency attempt did not get distribution, but the dashboard is real and working.

4. Right side contains the artifact.

   Use a dashboard screenshot, walkthrough video frame, or intentional media placeholder. The media well should look like a polished product preview, not an unfinished to do area.

5. Below the story, include four compact proof chips.

   Recommended chips: Laravel, Inertia, React, Docker on Hetzner.

6. The workflow should become a small three step path, not a separate large card.

   Recommended steps: Capture sample lead, enrich and assemble, publish demo.

7. Applied AI features should be mentioned in one compact line on the home page, then expanded on the project detail page.

8. CTAs should use the existing button language.

   Recommended CTAs: View case study, Watch walkthrough.

Avoid:

1. Cyan primary buttons.
2. Emerald badges.
3. Large black panels.
4. Placeholder grids.
5. Separate product integration cards on the home page.

### Projects

Projects should feel like proof files, not a generic portfolio gallery.

Each card should answer:

1. What was built.
2. What stack was used.
3. What problem it proves.
4. Whether the content is complete or still a placeholder.

The Light Code Labs Dashboard should be visually first and slightly stronger, but not in a different design universe.

### Timeline

Keep the older timeline visual language. Update copy only.

The timeline should explain the journey from WordPress and PHP into Laravel, React, infrastructure, ecommerce, and product work.

Important moments to preserve:

1. Early WordPress and PHP foundation.
2. ViViFi and client work.
3. Chrome extension product experience.
4. NFT projects and the burnout travel chapter.
5. WordPress return and SunnySide proof.
6. Light Code Labs Dashboard and Laravel focus.

### Skills

Skills should be grouped by hiring relevance.

Recommended order:

1. Laravel application development.
2. React and TypeScript product UI.
3. Databases, APIs, queues, and integrations.
4. Infrastructure and hosting.
5. WordPress and PHP foundation.
6. Shopify and ecommerce support.
7. Applied AI product features.

The layout should stay calm. Avoid turning skills into a wall of badges.

### Gear

Keep the bento grid and image based cards.

The gear section should support the personal brand. It should not become a technical stack section.

The copy can shift from WordPress heavy tooling to a broader development setup, but the visual pattern should stay close to the old version.

### Books

Books can stay as a personal section if the page length still feels good after the Laravel proof is tightened.

If included, place it after the primary technical proof, timeline, and skills. It should feel like personality and taste, not a hiring argument.

### FAQ

Keep the chat style accordion. Rewrite the content for the Laravel job target.

The FAQ should answer practical hiring questions:

1. What Laravel experience do you have?
2. What is the Light Code Labs Dashboard?
3. How does WordPress fit now?
4. Do you know React and TypeScript?
5. Can you work with infrastructure?
6. Are the dashboard demo links real or placeholders?

### Letter

The letter should stay first person and honest.

It should not sound like a cover letter template. It should feel like Kelvin explaining the transition and why Laravel is now the focus.

## Placeholder Rules

Placeholders are allowed, but they must look intentional.

Use placeholders for:

1. Walkthrough video.
2. Demo login.
3. Generated sample site.
4. Additional WordPress work.
5. Shopify work.

Rules:

1. A placeholder should have one clear label.
2. A placeholder should explain what will replace it.
3. A placeholder should use the same purple glass surface.
4. A placeholder should not use dashed borders as the main visual treatment.
5. A placeholder should never look like broken production UI.

## Content Hierarchy

Recommended home page order:

1. Hero.
2. Proof Points.
3. Light Code Labs Dashboard feature.
4. Project Proof.
5. Timeline.
6. Skills.
7. Letter.
8. Gear.
9. Books, optional.
10. FAQ.
11. Contact.

This order keeps the money proof high while preserving the personal world that made the older site feel right.

## Redesign Acceptance Criteria

Before a section is considered done, it must pass these checks.

1. It feels like it lives on the same cosmic purple page as Proof Points.
2. It uses the same surface language as the existing good sections.
3. It does not introduce a new dominant color system.
4. It does not place cards inside cards.
5. It has one clear purpose.
6. It does not over explain what another section already explains.
7. It has enough breathing room on mobile and desktop.
8. It uses real artifacts where possible.
9. It treats placeholders as intentional content slots.
10. It supports the Laravel developer story without erasing the journey.
